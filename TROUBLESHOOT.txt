TROUBLESHOOTING - Port 80 Not Working
================================================================================

ISSUE: http://ctrader.emmanuelshekinah.co.za/webhook returns 404
       http://ctrader.emmanuelshekinah.co.za:25345/webhook works fine

ROOT CAUSE: Dokploy is managing Nginx and overriding the configuration

================================================================================
QUICK FIX (Recommended)
================================================================================

1. SSH into VPS:
   ssh root@ctrader.emmanuelshekinah.co.za

2. Run the force fix script:
   cd /root
   bash fix-port-80.sh

3. Test it works:
   curl -X POST http://ctrader.emmanuelshekinah.co.za/webhook \
     -H "Content-Type: application/json" \
     -d '{"symbol":"XAUUSD","action":"SELL","price":"3345.12","time":"2026-05-27T10:00:00Z"}'

Expected response:
   {"status":"success","message":"Alert received and stored","symbol":"XAUUSD","action":"SELL"}

================================================================================
MANUAL FIX (If script doesn't work)
================================================================================

1. Stop Nginx:
   sudo systemctl stop nginx

2. Edit Nginx config:
   sudo nano /etc/nginx/sites-available/ctrader.emmanuelshekinah.co.za

3. Replace entire file with this:

---BEGIN CONFIG---
server {
    listen 80;
    listen [::]:80;
    server_name ctrader.emmanuelshekinah.co.za;

    location / {
        proxy_pass http://127.0.0.1:25345;
        proxy_http_version 1.1;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Content-Type $content_type;
        
        proxy_buffering on;
        proxy_buffer_size 4k;
        proxy_buffers 8 4k;
        proxy_busy_buffers_size 8k;
        
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    location /webhook {
        proxy_pass http://127.0.0.1:25345/webhook;
        proxy_http_version 1.1;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Content-Type $content_type;
        
        proxy_buffering on;
        proxy_buffer_size 4k;
        proxy_buffers 8 4k;
        proxy_busy_buffers_size 8k;
    }

    location /signal {
        proxy_pass http://127.0.0.1:25345/signal;
        proxy_http_version 1.1;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /health {
        proxy_pass http://127.0.0.1:25345/health;
        proxy_http_version 1.1;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        
        access_log off;
    }
}
---END CONFIG---

4. Save and exit (Ctrl+X, Y, Enter)

5. Test configuration:
   sudo nginx -t

6. Start Nginx:
   sudo systemctl start nginx

7. Test endpoints:
   curl http://localhost/health
   curl -X POST http://localhost/webhook \
     -H "Content-Type: application/json" \
     -d '{"symbol":"TEST","action":"BUY","price":"1.0","time":"2026-05-27T10:00:00Z"}'

================================================================================
COMMON ISSUES
================================================================================

Issue: "Address already in use" on port 80
Fix:
  sudo lsof -i :80
  sudo kill -9 <PID>
  sudo systemctl start nginx

Issue: Nginx won't start
Fix:
  sudo nginx -t  (check for errors)
  sudo systemctl restart nginx
  tail -f /var/log/nginx/error.log

Issue: Port 80 still returns 404
Fix:
  sudo systemctl restart nginx
  sudo nginx -T | grep -A 50 "location /webhook"
  tail -f /var/log/nginx/error.log

Issue: Dokploy keeps overriding config
Fix:
  Disable Dokploy's Nginx management:
  1. Access Dokploy dashboard
  2. Go to application settings
  3. Disable "Nginx" or "Reverse Proxy" option
  4. Redeploy application
  5. Run fix-port-80.sh again
